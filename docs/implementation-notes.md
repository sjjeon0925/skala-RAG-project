# 설계서 반영 기록

기준 브랜치는 `feat/agentic-rag-evidence-workflow`의 `c934664`이다. 기존의 의존성 주입, 병렬 Graph, DEMO, 실행 로그, 오류 전파 구조를 유지하고 설계서와 `수정방안/2.md`의 차이를 반영했다.

- State에 `search_queries`를 추가했으며 Query Rewrite가 이 값과 `retry_count`를 함께 갱신한다.
- 시장·이해관계자·데이터센터 평가 기준을 설계서 3.1/3.2와 맞췄다.
- 7개 PDF 116쪽을 manifest로 관리하고, 표 페이지는 전체 페이지를 인용 parent로 보존하면서 400토큰 child를 검색한다.
- Dense 10개와 BM25 10개를 RRF로 합친 뒤 최종 5개를 반환한다. 기본 overlap은 50토큰이다.
- 기술×기준별로 검색하고, 최초 검색과 대체 검색 1회로 제한한다. 대상 시스템·상위 생태계·별도 비교 시스템을 구분한다.
- 인용 문자열, 수치·단위·조건, 기술 귀속을 코드로 검사한 뒤 별도 의미 검증을 거친다.
- Fan-in은 합류만 담당한다. 보고서 Agent가 본문에 실제 인용한 출처만 `references`에 저장한다.
- 채택한 반대 근거는 synthesis와 보고서에 반드시 남기며, 보고서 저장 전에 수치·단위·실험 조건 연결을 검사한다.

TRL 단계 문구는 설계서의 공개 정보 기반 추정 원칙과 1~9단계 정의를 사용한다. 별도의 강의 가이드 표가 저장소에 없으므로 공식 인증값으로 취급하지 않는다.
